I'm building a web scraper for a hackathon project (SIH26056 — Real-time
Airfare Price Index for India). I need a Python scraping pipeline that:

GOAL
Scrape live airfare data from Indian airline/OTA sites for a fixed set of
city-pair routes and multiple advance-booking windows, extract it into
clean structured records using an LLM, and write it to a Postgres database.

ROUTES (city-pair basket)
DEL-BOM, DEL-BLR, BOM-BLR, DEL-CCU, BLR-HYD, MAA-DEL

ADVANCE WINDOWS
T+1, T+7, T+15, T+30, T+45 days from today

TARGET SOURCES (start with 2, make it easy to add more later)
- One airline site (e.g. IndiGo or Air India)
- One OTA (e.g. Ixigo or Cleartrip)

ARCHITECTURE
1. `fetcher.py` — uses Playwright (headless) to load the flight search
   results page for a given route + date, waits for fare content to
   render, and dumps the relevant page text/HTML (not the whole page,
   just the fare-listing section if selectable).

2. `extractor.py` — sends the raw fetched content to an LLM and asks it
   to return STRICT JSON matching this schema:
   {
     "flights": [
       {
         "carrier": string,
         "departure_time": string,
         "base_fare": number,
         "taxes": number,
         "udf": number | null,
         "convenience_fee": number | null,
         "total_fare": number
       }
     ]
   }

   IMPORTANT — make the LLM provider model-agnostic, not hardcoded:
   - Both models run on NVIDIA NIM's OpenAI-compatible endpoint:
     base_url = "https://integrate.api.nvidia.com/v1"
   - Read the model name from an env var LLM_MODEL, supporting at least:
     - "deepseek-ai/deepseek-v4-pro"
     - "z-ai/glm-5.2"
   - Since both are OpenAI-compatible, this should just be a single
     client instantiation using the openai python SDK pointed at NIM's
     base_url, with model=os.environ["LLM_MODEL"] passed per-call — no
     provider-specific branching needed.
   - Keep prompts sent to the model as short/targeted as possible (only
     the fare-listing section, not the full page) to avoid output
     truncation issues some testers have reported on GLM-5.2 via NIM.
   - Validate the response against the schema (pydantic) before
     accepting it. If parsing/validation fails, retry once with a
     stricter "return ONLY valid JSON, no markdown fences" instruction,
     then log and skip if it still fails.
   - Add a `--model` CLI flag on main.py that overrides LLM_MODEL, so I
     can run the same route/source through both models from the command
     line for a quick side-by-side comparison.
   - Log which model was used on every extraction record (add a
     `model_used` column, see schema below) so I can later compare
     accuracy/reliability between the two from the database directly.

3. `db.py` — writes validated records into a Postgres table (I'll be
   using Supabase) with this schema:
   CREATE TABLE fares (
     id SERIAL PRIMARY KEY,
     origin TEXT, destination TEXT,
     carrier TEXT, source TEXT,
     advance_window_days INT,
     base_fare NUMERIC, taxes NUMERIC,
     udf NUMERIC, convenience_fee NUMERIC,
     total_fare NUMERIC,
     model_used TEXT,
     scraped_at TIMESTAMP DEFAULT now()
   );

4. `main.py` — orchestrates: loops over routes × advance windows ×
   sources, calls fetcher → extractor → db, with:
   - a delay of 3-5 seconds between requests (randomized)
   - a check of the target site's robots.txt before scraping it, skip
     disallowed paths
   - retry with backoff on failure (max 2 retries)
   - structured logging (route, source, model used, success/failure,
     record count)
   - respect NVIDIA NIM's free-tier rate limit (~40 requests/min,
     shared across whichever model is active) — add a simple rate
     limiter/queue around extractor.py calls

5. `compare_models.py` — a small standalone script: takes one already-
   fetched page (or re-fetches one route/source), runs extraction
   through BOTH models, and prints a side-by-side diff of the parsed
   JSON plus timing for each, so I can manually judge which one parsed
   the page more accurately before committing to one for the full run.

CONFIG
Read secrets/config from a .env file: NVIDIA_API_KEY, SUPABASE_URL,
SUPABASE_KEY, LLM_MODEL (default "z-ai/glm-5.2"). Include a .env.example
with placeholder values and both model name options listed as comments.

DELIVERABLES
- requirements.txt
- README.md with setup steps (Playwright install, env vars, how to run
  once locally, how to run compare_models.py, how this is meant to run
  on a schedule via GitHub Actions — include a sample
  .github/workflows/scrape.yml that runs main.py every 4 hours)
- Basic error handling throughout — a single scrape failure for one
  route/source should not crash the whole run

Start by building fetcher.py + extractor.py for ONE route (DEL-BOM) and
ONE source, then compare_models.py so I can validate both models' JSON
